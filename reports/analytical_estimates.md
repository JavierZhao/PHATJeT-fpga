# PHAT-JeT — analytical per-component estimates (Track A)

**These are op-count arguments for ONE configuration, not the measured
results.** The rebuttal numbers live in `synthesis_table.md`, which reports
traced da4ml costs across the full accuracy/area curve. This document exists
as the handoff's analytical fallback and as a sanity check on those traces.
Its most durable finding -- that GMP's scatter/gather is one-hot routing
rather than arithmetic -- was later confirmed by trace: GMP costs ~0 LUT.

Generated by `analytical_estimates.py`. **No synthesis was run.** These are
counting arguments derived from the topology in `phat_jet_k3.py`, intended as
the handoff's documented fallback and as a sanity baseline for the da4ml
numbers from `extract_hw.py`.

Config: N=64 particles, 3 feats, d_model=16, 4 heads, patch=8 (8 patches), GMP 8x8 grid, 3x3 depthwise, FFN 16, 5 classes.
Datapath 16-bit. Clock 3.33 ns (300 MHz).

Of these, only **18,432** (11.8%) are data-dependent; the rest have constant coefficients.

## Notes per component

- **GMP (indicators+scatter+DWConv+gather+pointwise)** — scatter/gather are one-hot routing, not multiplies
- **Local patch attention (all 8 patches, parallel)** — 8 independent patches, 8x8 attention each
- **Patch pooling (mean) + global MHSA (8 tokens) + broadcast** — mean pool is a shift; Repeat is wiring
- **GlobalMaxPool + head Dense(16->16)+Dense(16->5)** — max pool over 64 particles = comparator tree

## Latency

Critical path is sequential across components: **110 op-levels**.
At 2-4 levels per 3.33 ns cycle: **28-55 cycles = 93-183 ns**.
II = 1 (one jet per clock) for the fully-unrolled mapping.

The levels-to-cycles conversion is the softest assumption in this document; the op-level depth itself is exact given the topology.

## Storage

- Weights: 3,845 x 16 b = 61,520 b (7.5 KiB)
- GMP grid buffer: 8x8x16 x 16 b = 16,384 b
- Particle activations: 64x16 x 16 b = 16,384 b
- Total ~92 Kib, i.e. ~6 BRAM18 *if* buffered.
  At II=1 fully unrolled these live in registers/LUTs and BRAM = 0, which is what `extract_hw.py` reports.

## DSP mapping

Per the handoff's fallback spec, DSP = MACs / II:

| Mapping | II | DSP | Comment |
|---|---:|---:|---|
| Generic HLS, fully parallel | 1 | 155,984 | infeasible on VU13P (12,288 DSP) — motivates the da4ml mapping |
| Generic HLS, folded | 64 | 2,438 | fits comfortably |
| da4ml constant shift-add | 1 | 18,432 | only data-MACs need multipliers; const-MACs become LUT logic |

The third row is the architecturally interesting one: constant-folding removes 88% of the multipliers, leaving 18,432 genuine multiplies, all inside attention.
